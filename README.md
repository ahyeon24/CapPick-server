# 캡픽 (CapPick) — API 서버

**캡픽(스크린샷 검색·정리 아이폰 앱)의 서버. AI 호출을 중계하고, 비용이 드는 작업을 안전하게 처리한다.**

> 테스트 129개 통과 · AI 분석 비용 장당 **1.4원 → 0.85원**, 분류 비용 **1.85원 → 0.80원**

관련 저장소: [CapPick-ios](https://github.com/ahyeon24/CapPick-ios)(앱) · [CapPick-eval](https://github.com/ahyeon24/CapPick-eval)(AI 비용·품질 측정) · [CapPick-docs](https://github.com/ahyeon24/CapPick-docs)(기획·화면·API 명세)

## 서버의 역할

| 하는 일 | 하지 않는 일 |
|---|---|
| 로그인 없이 앱 설치 단위로 요청 확인 | 캡처·폴더 영구 저장 (기준 저장소는 아이폰의 로컬 DB) |
| AI 작업(내용 분석·폴더 분류) 접수와 비동기 처리 | 검색 (검색은 앱이 기기에서 처리, 검색어가 서버로 오지 않음) |
| 작업 결과 임시 보관 | AI 비밀 키를 앱에 전달 |
| 사용량 기록, 하루 예산과 설치별 한도로 비용 보호 | |

## API

| 메서드 | 경로 | 내용 |
|---|---|---|
| POST | `/v1/installations/challenges` | 설치 확인용 1회용 challenge 발급 (5분) |
| POST | `/v1/installations` | 설치 등록, 자격 발급 |
| POST | `/v1/installations/credentials/renew` | 자격 갱신 |
| POST | `/v1/jobs` (multipart) | 스크린샷 내용 분석 작업 접수 → 202 |
| POST | `/v1/jobs` (JSON) | 폴더 분류 작업 접수 → 202 |
| GET | `/v1/jobs/{id}` | 작업 상태·결과 조회 (앱이 폴링) |
| GET | `/v1/usage` | 사용량 조회 |
| POST · GET | `/v1/data-deletions` · `/{id}` | 이 설치의 서버 데이터 삭제 요청·상태 |

## 비용이 드는 작업을 다루는 방법

AI 호출 한 번이 곧 비용이라, 같은 일이 두 번 일어나거나 실패한 작업에 비용이 매겨지지 않게 하는 데 집중했다.

- **같은 요청 중복 방지**: 모든 작업 요청에 `Idempotency-Key`를 받는다. 같은 설치·같은 키로 다시 오면 AI를 다시 부르지 않고 기존 작업을 돌려준다. 같은 키인데 내용이 다르면 409로 거부한다.
- **사용량 예약 → 확정 / 해제**: 작업을 받을 때 사용량을 예약하고, 성공하면 확정, 실패하면 해제한다. 실패한 작업은 사용량에 넣지 않는다.
- **비용 보호 2단계**
  - 전체 하루 예산: 모든 설치를 합친 오늘 요청 수가 한도에 닿으면 `429 DAILY_BUDGET_EXHAUSTED`로 바로 거부한다. "오늘"의 기준은 Gemini 한도가 리셋되는 **태평양 시간 자정**에 맞췄다.
  - 설치별 한도: 설치 하나가 분석할 수 있는 장수를 넘으면 `429 QUOTA_EXCEEDED`. 유료 전환 때 "처음 N장 무료"가 들어갈 자리다.
- **삭제 중 늦게 도착한 결과 차단**: 데이터 삭제 후에 워커 결과가 도착하면, 상태 전이가 모두 "있으면 갱신" 방식이라 아무것도 저장되지 않는다. 삭제가 진행 중이면 새 작업도 `409 DELETION_IN_PROGRESS`로 막는다.

## AI 응답을 그대로 믿지 않는 설계

폴더 분류는 모델이 폴더마다 `match / no_match / uncertain`을 답하게 한다. 서버는 응답을 요청과 대조해 다음을 보장한다.

- 모델이 **빠뜨린** 폴더는 "아님"이 아니라 `uncertain`으로 채운다. 판정이 없는 걸 "아니다"로 둔갑시키면 분류가 조용히 틀어진다.
- 모델이 **지어낸** 폴더 ID는 버린다.
- 기준 버전 값은 모델 응답이 아니라 요청 값을 그대로 쓴다.

그래서 앱은 항상 "요청한 폴더 수 = 응답 판정 수"를 믿을 수 있다. 분류 규칙(간접 연관성만으로 추측하지 않기, AI가 폴더를 새로 만들지 않기)은 기획서의 문장을 그대로 프롬프트로 옮겼다.

## AI 비용 측정과 개선

같은 테스트 이미지 18장으로 실제 Gemini를 호출해 쟀다. (유료 단가·환율 1,400원으로 계산한 추정치, 측정 스크립트는 [CapPick-eval](https://github.com/ahyeon24/CapPick-eval))

| 개선 | 전 | 후 | 방법 |
|---|---|---|---|
| 내용 분석 비용 (장당) | 약 1.4원 | **약 0.85원** | 글자 인식을 앱(Apple Vision)으로 옮기고, 글자가 함께 오면 모델에게 OCR을 시키지 않는 프롬프트로 호출 |
| 폴더 분류 비용 (장당, 폴더 5개) | 약 1.85원 | **약 0.80원** | 36자 UUID 대신 1, 2, 3 번호로 주고받기, 근거 문장은 match일 때만 |
| 같은 요청의 판정 흔들림 | 10 / 90 | **2 / 90** | `temperature 0` |
| 캡처 1장당 AI 호출 | 2회 | **1회** | 임베딩 생성을 앱으로 옮겨 서버는 분석 호출 하나만 |

- 무료 한도는 모델마다 따로 매겨진다. 분류를 가벼운 모델로 분리해서, 분석과 분류가 한 모델의 하루 한도를 나눠 쓰던 때보다 하루 처리 장수를 늘렸다.
- 검색 품질을 위해 요약에 관련 단어를 덧붙이면서 비용이 0.85원 → 0.92원으로 다시 조금 올랐다. 품질을 위해 일부러 택한 비용이다.

## 실제로 겪은 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 작업이 "RUNNING이어야 하는데 QUEUED" 예외로 실패 | 같은 클래스 안에서 `this.`로 `@Transactional` 메서드를 불러 Spring 프록시를 거치지 않음 | 상태 전이를 별도 빈(`JobStateTransitions`)으로 분리 |
| 고친 뒤에도 **같은 예외가 다시** 발생 | 트랜잭션이 커밋되기 전에 `@Async` 워커가 먼저 실행돼, 아직 저장되지 않은 작업을 찾지 못함 | 워커 실행을 `afterCommit` 콜백으로 미룸. 작업 6건을 연속으로 넣어 재현 0건 확인 |
| 서버 시작 시 `BeanCurrentlyInCreationException` | 삭제 서비스와 삭제 워커가 서로를 의존 | 상태 전이 빈(`DeletionStateTransitions`)을 분리해 순환을 끊음 |
| Gemini에 이미지 형식을 항상 PNG라고 보냄 | MIME 타입 하드코딩 | 업로드된 실제 형식을 그대로 전달, 회귀 테스트 추가 |

앞의 세 문제는 모두 **Mockito 단위 테스트는 통과했지만**, 실제 서버를 띄우거나 Spring 컨테이너를 올리는 테스트에서만 드러났다. 그래서 단위 테스트와 별개로 curl과 실제 Gemini 호출로 끝까지 돌려 보며 확인했다.

Spring Boot 4에서 Flyway와 `RestClient` 자동 설정이 별도 모듈로 분리돼, 의존성을 추가해도 동작하지 않던 문제도 공식 문서와 이슈로 원인을 찾아 해결했다.

## 보안

- **자격**: 32바이트 랜덤 토큰을 한 번만 평문으로 주고, 서버에는 SHA-256 해시만 저장한다. JWT 대신 이 방식을 고른 이유는 즉시 폐기가 쉽기 때문이다.
- **설치 확인**: Apple App Attest 검증(인증서 체인, nonce, 서명)을 구현했다. 운영 프로필에서 개발용 우회 모드를 켜면 서버가 시작을 거부한다.
- **소유권**: 모든 조회 쿼리에 설치 조건을 넣어 다른 설치의 데이터에 접근할 수 없다.
- **로그**: 사용자 콘텐츠와 비밀 값을 남기지 않는다.

## 현재 상태

- 작업 큐는 서버 안의 스레드풀이다. 서버가 재시작하면 진행 중이던 작업이 사라진다. 별도 큐는 부하를 확인한 뒤 도입할 예정이다.
- App Attest는 Apple Developer Program 미가입으로 실제 기기 데이터가 아니라 합성 데이터 테스트로만 검증했다. 지금은 개발용 우회 모드로 동작한다.
- 배포하지 않았다. 로컬에서 앱과 연결해 동작을 확인했다. 환경별 설정 분리도 아직이다.

## 기술 스택

Java 21 · Spring Boot 4.1 · Spring Data JPA · PostgreSQL · Flyway · RestClient · Gemini API(structured output) · JUnit 5 · Mockito · MockRestServiceServer

## 실행

```bash
# PostgreSQL에 cappick_dev 데이터베이스가 있어야 한다
GEMINI_API_KEY=... ./gradlew bootRun   # http://localhost:8080
./gradlew test                          # 테스트 129개
```

API 키는 환경변수로만 받는다. 코드와 저장소에 넣지 않는다.
